# الصرف الكامل واختيار اللوتات — 2026-11-02

النطاق: تبويبات PMV2 وتذاكر فرق الصيانة والصرف التشغيلي في شاشة طلبات المستودع. لا صرف جزئي، ولا تعديل لدورة المرتجعات أو الاستلام أو الاعتمادات.

## السلوك

- `صرف بالأقدم` يختار اللوتات المتوافقة في وحدة الصرف داخل مخزن الاحتياج، بترتيب تاريخ إنشاء اللوت ثم رقمه. اختيار اللوت لا يتطلب مسح باركود؛ يُحل رمز التتبع داخليًا عند استدعاء الكاتب الحالي.
- `اختيار اللوتات` يفتح جدولًا بالسهم؛ يمكن تحديد عدة لوتات وتوزيع كامل الكمية بينها. الرصيد `[2,3,5,1]` واحتياج6 ينتجان تلقائيًا `2+3+1`، أو يدويًا `5+1`. الاختيار الناقص أو الزائد أو المكرر أو الأجنبي يُرفض.
- تبقى اللوتات الفيزيائية والتكلفة وسندات الصرف والمستلم ومرجع المهمة/البلاغ/الأمر محفوظة لدى الكتّاب الحاليين. البديل المعتمد يحتفظ بنسبة تغطيته للاحتياج الأصلي؛ لا تُقرّب كمية غير قابلة للتمثيل.
- فشل أي لوت في العملية يلغي كل خصوماتها. في PMV2 تمرر خدمة المستودع المعاملة نفسها إلى كاتب الصرف وقارئ السند وربطه بالمهمة. مسار الاستلام الذاتي التاريخي المنفصل لم يُعد تصميمه بهذا التعديل؛ مسار المستودع يستخدم المعاملة الكاملة حتى إن أغفل مستدعٍ قديم حقل الاختيار.
- الصرف التشغيلي المُجهّز يظل زر تأكيد واحدًا لكل الطلب، وكل بنوده في معاملة واحدة. لا دفعات صرف جزئي ولا جداول جديدة.
- النقص يمنع الصرف. استكمال نقل مواد PMV2 والتذاكر من الرئيسي لمخزن الفريق ودورة الشراء القائمة باقٍ كما هو. في الصرف التشغيلي أصبح الرصيد الموجب غير الكافي يعرض شراء العجز فقط بدل حصر الشراء في الرصيد الصفري؛ الرابط النشط يعاد استخدامه ولا يُنشأ شراء ثانٍ.

## الصلاحيات والقراءات

- لم يُضف RPC جديد أو دور جديد. مدخلات الاختيار اختيارية في الإجراءات القائمة وتُراجع عند التنفيذ داخل المعاملة.
- تفاصيل لوتات التذكرة تُطلب للاحتياج الذي فتحه المستخدم فقط عبر خيار `issueNeedId` في قارئ `balances` الحالي. يُفحص الدور الحقيقي قبل أي إسقاط لصلاحية المراقب، ثم حارس الإسناد وحالته والجولة والمخزن. لا استعلامات لوتات خلفية لكل بطاقة مغلقة.
- قائمة PMV2 تعيد تفاصيل اللوتات من القراءات الموجودة أصلًا؛ لا استعلام إضافي لكل لوت أو تكرار قارئ صلاحيات داخل حلقة جديدة. الخيارات تُراجع مجددًا عند الكتابة ولا يُعاد استخدام قرار صلاحية محفوظ عالميًا.

## التحقق

- `node tools/warehouse-lot-selection/run.mjs`: نجحت275حالة معزولة في15ملفًا. تشمل FIFO والاختيار اليدوي الكامل، منع الصرف الجزئي بالواجهة وAPI القديم، اللوت الأجنبي والوحدة والكميات غير الدقيقة، شراء العجز وعدم تكراره، rollback لآخر سند، وحارس قراءة لوتات التذكرة وطلبات مستقلة متعاقبة. اختبار PMV2 الجديد يختبر منسق المعاملة ببدائل للكاتب والرابط؛ اختبارات الصرف التشغيلي تشغّل الكاتب الفيزيائي الفعلي على بيانات ذاكرة.
- `node tools/read-scope-perf/run.mjs`: نجحت401حالة.
- `node tools/inventory-books/run.mjs`: نجحت100حالة.
- بناء الإنتاج `npm run build`: ناجح.
- `node tools/warehouse-lot-selection/preview.mjs`: تشغيل المكون الفعلي في Chromium ببيانات وهمية والشبكة محجوبة، بعرض1280و390. تحقق من FIFO، فتح السهم، تعطيل التأكيد عند5من6، وتفعيله بعد5+1، دون تجاوز عرض الصفحة أو أخطاء React. الصور والتقرير في `tmp/warehouse-lots-preview/`.
- الفحص النوعي العام للمشروع غير نظيف؛ التشخيصات المتبقية في ملف PMV2 المعدل تخص تعبيرات Map/Set السابقة مع إعداد target الحالي، ولا تشخيص متبقٍ في الإضافات الجديدة. لم يُقدَّم الفحص العام على أنه ناجح.
- فحص PMV2 النصي التاريخي `pmv2-phase4-team-warehouse-issue-delivery.node.mjs`:17ناجح و7إخفاقات. أُعيد تشغيله على محتوى HEAD قبل التعديل وثبتت الإخفاقات السبعة نفسها؛ بعضها يبحث عن نص عربي استُبدل سابقًا بمفاتيح ترجمة. لم تُوسَّع المهمة لإصلاحه ولم يُحسب ضمن الاختبارات الناجحة أعلاه.

## قاعدة البيانات والنشر

لا SQL أو ترحيل مطلوب لهذا التعديل؛ يستخدم الجداول الحالية. لم يحصل اتصال بأي قاعدة، أو تغيير `.env`، أو نشر، أو تسجيل صرف حقيقي. المعاينة واختبارات الذاكرة لا تُعد قبولًا حيًا على `copycmms2` أو `cmms`. ملف كشف الإكسل والمهمات المؤجلة الأخرى باقية خارج النطاق.
