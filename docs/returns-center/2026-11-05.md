# مركز المرتجعات — تنظيم الشاشات الحالية

## النطاق

تنفيذ موافقة المستخدم بتاريخ 2026-11-05: تجميع المرتجعات في مركز واضح دون إعادة بناء أنواعها أو تغيير المخزون أو التسويات أو الاعتمادات أو تعويض البديل. المسار الجديد `/returns-center` داخل تخطيط البرنامج الحالي. لا RPC أو جدول أو عمود أو SQL أو متغير بيئة جديد. لم تُفتح قاعدة حية أو تُنفذ عمليات على بياناتها أو يُنشر الكود في هذه المهمة.

## قبل وبعد

| الجزء | قبل التنفيذ | بعد التنفيذ |
|---|---|---|
| الدخول | روابط منفصلة لإنشاء المرتجع وسجله ومتابعة المندوب، إضافة إلى تبويبات المستودع | مدخل «مركز المرتجعات» واحد في القائمة، وزر إنشاء واحد للمخولين؛ الروابط القديمة تبقى صالحة |
| المورد والتعويض | المكوّن نفسه موزع داخل شاشة المستودع وطلبات الشراء وصفحة المندوب | قسم «الموردون والتعويض» يعيد استعمال SupplierReturns نفسه مع الجارية والمكتملة |
| مرتجعات المواد | ضمن أقسام طلبات مواد PMV2 والتذاكر وتفاصيل الصرف التشغيلي | قسم «مرتجعات الفنيين والفرق» بثلاثة مصادر؛ يعرض إجراءات الإرجاع الحالية فقط |
| رفض المواصفات | قائمة مجاورة للمتابعات والسندات في شاشة المستودع | قسم مستقل واضح بأن الصنف ينتظر بدء الإرجاع؛ الرفض لا ينفذ الإرجاع تلقائيًا |
| السندات | ضمن قائمة مختلطة مع إجراءات أخرى | قسم «سندات المرتجعات» مع اختيار الكل/الموردين/الجهات والفنيين، والطباعة الحالية نفسها |
| البحث | غير موجود في بعض القوائم الحالية | بحث فوري داخل القسم المختار، مع توضيح أنه للصفحة الحالية عند ترقيم القائمة |
| تحميل البيانات | بعض الشاشات تجمع قراءات أقسام متعددة | يُركب القسم المختار وحده؛ في تضمين PMV2 تعطل قراءتا الانتظار والصرف، وفي التشغيل تعطل قراءة المخزون والاعتماد والصرف |
| العودة من الإنشاء | إلى سجل المستودع القديم | يعود الإدخال المفتوح من المركز إلى قسمه؛ الإنشاء المفتوح من المسار القديم يحتفظ بوجهته السابقة |

## الأقسام وما يبقى كما هو

1. **الموردون والتعويض:** نفس status/list وقرارات استلام المندوب أو رفضه مع السبب، وإعادة التسليم، واختيار نفس الصنف أو البديل أو الاسترداد، وقرارات المنشئ وخطة التعويض. لم تتغير حمولات الأوامر أو مفاتيح منع التكرار أو تحقق المراحل. فاصل الجارية/المكتملة وحجم الصفحة البالغ 20 سجلًا من الخادم كما كانا.
2. **مرتجعات الفنيين والفرق:** تذاكر الصيانة تعرض قسم returns في TicketWarehouseRequests وExecutionPanel؛ PMV2 يعرض pendingReturns وإجراء confirmPendingReturn بلوتاته وكمياته نفسها. الصرف التشغيلي يعرض طلبات الصرف الحالية ثم سنداتها عند اختيار طلب؛ ليست قائمة مصطنعة لمرتجعات معلقة، ولا يُنشأ مسار طلب مرتجع جديد له. يُستخدم OperationalReturnPanel وإجراء returnMaterial الأصليان.
3. **مرفوضات المواصفات:** نفس RejectedSpecificationReturns وقراءة الرفض وحجم الصفحة البالغ 10 سجلات، وزر يفتح نموذج المرتجع الحالي بسياق المواصفة والعودة. لا حركة مخزون أو خصم جديد بمجرد عرض القسم.
4. **السندات:** استُخرج عرض المستندات من WarehouseReturnsList إلى WarehouseReturnDocuments. بقيت returnDocuments.list وprintReturnDocument وincrementPrint نفسها؛ عداد الطباعة يتغير فقط بفعل الطباعة الصريح كما كان.

الكمية والوحدة واللوت والمورد وسند الاستلام أو الصرف ومرجع طلب الشراء والتكلفة والتسويات تبقى بقرارات وحراس الخدمات الموجودة. إدخال استخدام الفني وإعلان المرتجع يظلان ضمن تنفيذ المهمة الحاليين، وليس داخل شاشة فني عامة جديدة.

## الصلاحيات

| الفئة | الأقسام في المركز |
|---|---|
| المستودع والمالك والأدمن | الأقسام الأربعة وإنشاء المرتجع |
| المندوب ومسئول المناديب | المورد والتعويض، للمسند إليهما بحسب قارئ الخادم القائم |
| الإدارة العليا | متابعة المورد ضمن نطاقها الحالي وسندات المرتجعات بصلاحيتها السابقة؛ دون معالجة استلام مواد الفنيين أو إنشاء المرتجع |
| الحسابات وبقية أدوار منشئي الطلبات المؤهلة أصلًا | متابعة الحالات التي يجيزها القارئ القائم؛ لا منحة لعرض جميع حالات المستودع أو سنداته |
| الفني وعضو IT والحراسة والمراقب | لا منحة جديدة للمركز؛ تظل شاشات التنفيذ والقراءات القديمة المسموحة كما هي |

قائمة الموردين في helper هي تقاطع صلاحيات الصفحة والخادم الموجودة فعلًا. تُفحص authenticatedUser النشطة قبل تركيب أي مكون؛ رابط tab/source غير مخوّل يعود إلى قسم مسموح ولا يُركب المصدر المحجوب. لم تُضف أسماء إجراءات إلى BUSINESS_ROLE_CAPABILITIES أو أي صلاحية كتابة.

## التنقل والبحث

- `?tab=suppliers|materials|specifications|documents`، ومصادر المواد `tickets|pmv2|operational`. التبديل يحفظ المسار في سجل المتصفح؛ البحث والاختيارات المحلية تُصفّر عند تغيير القسم أو المصدر أو الهوية.
- البحث داخل البيانات المصرح بها التي حُمّلت للقسم، وليس بحثًا عامًا عبر كل قواعد البيانات أو كل صفحات النتائج. تظهر عبارة الصفحة الحالية وعدد الظاهر/المحمّل في القوائم المرقمة. لم يتغير ترقيم الخادم أو المرشح التشغيلي الجارية/المكتملة.
- الروابط القديمة `/warehouse/return` و`/warehouse/returns` و`/warehouse-returns-followup` باقية. زر المرتجعات داخل طلبات الشراء يفتح المركز للمخولين بدل فتح نسخة مشتتة أخرى؛ رابط العرض القديم يبقى متوافقًا.
- `returnTo=returns-center` مع returnTab مسموح فقط يغير وجهة العودة للنموذج؛ لا يقبل رابطًا خارجيًا أو وجهة حرة، ولا يغير مصدر المرتجع أو قيمة الأمر.
- أخطاء القراءة وعدم إتاحة المتابعة تظهر بوضوح داخل المركز، ولا تتحول إلى «لا توجد مرتجعات» كاذبة. لا تُشغّل نماذج الإنشاء أو أي إجراء عند فتح المركز.

## الملفات

- الجديد: shared/returns-center.ts، ReturnsCenter.tsx، returnsCenter.ts للغات العربية والإنجليزية والأردية، WarehouseReturnDocuments.tsx، وreturnSearch.ts.
- التنقل: App.tsx وDashboardLayout.tsx وقاعدة صفحة المركز في roles.ts وbusiness-role-policy.ts ومفاتيح عنوان القائمة، مع رابط العودة في WarehouseReturn.tsx وزر PurchaseOrders.
- التضمين: خصائص اختيارية لا تغير افتراضات الصفحات القديمة في SupplierReturns وPurchaseSpecifications وTicketWarehouseRequests وPmv2WarehouseQueue وOperationalWarehouseRequests/OperationalIssueQueue. إضافة returnsOnly في ExecutionPanel تمنع فقط قراءة أرصدة غير مطلوبة داخل التضمين.
- لا تغييرات في server/routers أو server/_core أو server/supplier-return-followup أو drizzle أو قوالب السندات أو طباعة المرتجع. تغييرات server/tests تخص التحقق فقط؛ استُبدل اختبار نصي قديم لوجهة التنقل بتشغيل callbacks الحقيقية للنجاح دون رقم سند مع الوجهتين القديمة والجديدة.

## المعاينة والحدود

راجعت معاينات غلاف المركز الفعلي وCSS البناء مع fixtures محلية للأقسام، لا بيانات تشغيل حقيقية ولا بطاقات المعاملات الحية. اجتازت 12 حالة قياس على عروض 1365 و390 و320 بكسل دون تجاوز عرض أو قص تبويبات، وصفر أخطاء متصفح. HTML وPNG وlayout-metrics.json في tools/returns-center/artifacts، والباني في preview.mjs؛ الاعتراض الشبكي يمنع كل الطلبات في المعاينة.

لم يُجر قبول حي من متصفح الموقع أو أي مرتجع حقيقي أو تأكيد استلام أو طباعة حية. بعد تشغيل/نشر النسخة يلزم قبول المستخدم بحساب المستودع والمندوب والإدارة ضمن صلاحياتهم، واختيار المصادر والتصفية والعودة والطباعة. لا SQL إضافي أو تعديل ENV مطلوب لبناء المركز؛ تبقى مفاتيح إتاحة الميزات الموجودة كما هي. لا عودة إلى كشف الإكسل أو تطويرات المرتجعات المؤجلة خارج تجميع الشاشات.
