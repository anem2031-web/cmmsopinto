# حزم التسعير المعتمدة — صلاحية مستخدمين محددين

## الطلب والنطاق

إتاحة الوثيقة النهائية من مركز المستندات للمستخدمين `ANIS` و`ahmed1` وللأدمن والمالك، بقائمة واستعراض وطباعة بعد اكتمال اعتماد الحسابات والإدارة العليا. تبقى الأدوار السابقة على تبويباتها وصلاحياتها دون توسيع. لا اعتماد أو تسعير أو شراء أو تعديل مخزون في هذه الإضافة.

## حدود الصلاحية والتنفيذ

- المنح في `shared/approved-pricing-documents.ts` يستخدم اسم الدخول في سجل الهوية المصادق عليه، لا الاسم المعروض أو حقول الطلب. `approvedPricingDocumentProcedure` إجراء مركزي مغلق على `approvedPricingDocuments.listPage` من نوع query و`approvedPricingDocuments.pdf` من نوع mutation للقراءة/التوليد فقط. لا يبدل الدور ولا يشغّل إسقاط المراقب إلى admin. RPC الأدوار القائمة وحراسها لم تتغير.
- القارئ في `server/services/delegate-pricing-bundles/approved-reader.ts` يجلب معرف المستخدم واسم دخوله ودوره ونشاطه الحالي لكل عملية، ويرفض الهوية المفقودة أو المتغيرة أو المعطلة. عند منح الاسم المحدد يجب أن يشير اسم الدخول إلى سجل واحد فقط؛ الالتباس يمنع الاطلاع. لا memoization لهوية أو صلاحية عبر الطلبات.
- نطاق الموارد هو DPB المرسلة/المؤرشفة المكتملة فقط، عبر `approvedBundleCondition` ثم تطابق كامل أعضاء اللقطة مع العضوية الفعلية. لا يستخدم حالة رأس PO وحدها ولا يعرض جزءًا من حزمة غير مكتملة. `approvedBundleSnapshot` يعيد فحص الاعتمادات القائمة عند التوليد. ليس هناك توسيع لقراءة PO العام أو PDF المندوب.
- شرط الاعتماد والبحث والترقيم في SQL قبل إثراء الأعضاء. تُحمّل المعرفات المميزة بـ`readScopeChunks` و`groupReadRows` بحد500 ثم تُفحص كل حزمة مستقلة. الرد لا يعرض snapshots أو صور توقيع أو روابط تخزين. PDF يُولد عند كل استعراض/طباعة؛ لا يرجع من قرار قائمة سابق أو promise مشترك. لا كتابة على لقطة الحزمة أو ملفها الأصلي.
- مركز المستندات والقائمة الجانبية يضيفان الوصول للحسابين فقط إلى `/documents`. مستخدم لا يملك المركز سابقًا يرى القارئ وحده. من يملك المركز أصلًا يحتفظ بقوائمه ويختار التبويب الجديد. لا تُحمّل قوائم الطلبات أو المخزون عند فتح القارئ. زرا الاستعراض والطباعة يفتحان PDF المصادق عليه في عارض المتصفح؛ الطباعة من العارض كالمستندات القائمة.
- يعاد استخدام مفتاح حزم التسعير القائم؛ لا مفتاح أو schema أو SQL جديد.

## تفاصيل PDF التي طلبها المستخدم أثناء العمل

حسابات: صورة توقيع فقط بلا نص أو تاريخ اعتماد إلكتروني. الرئيس التنفيذي: «المهندس/ زكري بن عبدالله الزكري» ثابت وعريض وخانة توقيعه فارغة. مراجع الطلب: اسم فقط دون سطر الطلبات. تبقى بيانات الاعتماد الفعلية في السجل، وأرقام الأصناف ومقدمي الطلبات وتجميع الحزمة وأثر الرفض ونسخة المندوب دون تعديل.

## أدلة التحقق المعزول

- `node tools/approved-pricing-documents/run.mjs`: **368 حالة ناجحة،14 ملفًا**. منها43للمنح/نطاق الموارد،10للواجهة،18لقالب PDF؛ وتضم مجموعة المستندات والصلاحيات السابقة.
- اختبار RPC حقيقي من tRPC بالمستخدم الأصلي: السماح للحسابين والأدمن والمالك، المنع للأدوار الأخرى غير المسماة، رفض اسم عرض مماثل واسم دخول جزئي، رفض المعطل أو المستخدم المفقود، وعدم الوثوق بهوية ctx بديلة عن authenticatedUser. المنح الصريح للحساب المحدد لا يعتمد على دوره ولا ينتحل دور الحسابات.
- اختبار طلبين متتاليين بعد تغيير النشاط أو اسم الدخول أو الدور أو الاعتماد، وحجب التكرار في اسم الدخول؛ لا توقيع/توليد للمرفوض. اختبارات والد PO/دفعة/بند/إرسال مفقود، وحزمة بآباء مختلطين، وإرسال غير مكتمل، ولقطة بعضوية مختلفة، وانتشار فشل قاعدة البيانات.
- اختبار حزمة موحدة برفض جزئي: الإجمالي المقبول فقط في القائمة، الصفوف المجمدة محفوظة في PDF دون إعادة كتابة المصدر. إيقاف الميزة يعرض قائمة فارغة ويرفض PDF دون جلب جداول الوثائق.
- الأداء: قائمة50حزمة وألف عضو مع تكرار PO تستخدم4قراءات: الحساب الحالي، العدد، الصفحة، الأعضاء.1201معرف مكرر مرتين يُحمّل بثلاث دفعات500/500/201؛ لا قارئ منفرد داخل حلقة.
- الواجهة: تبويب للحسابين والأدمن والمالك فقط؛ تبويبات بقية الأدوار كما كانت، لا جلب غير نشط، وزرا الاستعراض والطباعة يطلبان PDF حديثًا لكل ضغطة. لا رابط مباشر إلى PO أو حقول اعتماد في القارئ.
- `node tools/read-scope-perf/run.mjs`: **401 حالة ناجحة،13 ملفًا**، دون تحميل بيئة أو قاعدة حية.
- بناء الإنتاج **ناجح**. المحاولة المقيدة الأولى تعثرت بسبب صلاحية قراءة مسار إعداد Vite؛ نجح نفس أمر البناء في التنفيذ المصرح به. `npm run check` غير نظيف بأخطاء سابقة في المشروع، منها تكرار Set في أجزاء قديمة من DashboardLayout؛ لم تظهر أخطاء في وحدات القارئ الجديدة أو الواجهة الجديدة.
- جُددت `output/pdf/DPB-approved-form-sample.pdf` بواسطة مولد HTML الإنتاجي المعزول وفُحصت صورة الصفحة بصريًا: المراجع بلا أرقام، الحسابات بلا تاريخ، الاسم التنفيذي عريض وتوقيعه فارغ. هذه معاينة ببيانات تجريبية وليست وثيقة اعتماد فعلية. لا طلب خارجي أو DB في المولد.

## حدود التسليم

لم يحصل اتصال قاعدة أو SQL أو تعديل `.env` أو نشر أو اختبار دخول حي للحسابين في هذه الجولة. بعد النشر يختبر المستخدم التبويب بالحسابين والأدمن/المالك، مع وثيقة مكتملة وأخرى معلقة وتجربة الطباعة. لا يُعد الاختبار المعزول ادعاءً بوجود التعديل على Railway قبل نشره. الأعمال المؤجلة السابقة محفوظة.
