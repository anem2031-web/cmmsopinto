# مسئول المناديب — 2026-11-04

## السلوك

- الدور الجديد `delegate_manager` يرث قدرات المندوب وحدود إسناده نفسها؛ لا يستعرض أصناف المناديب الآخرين ولا يراجع الأصناف أو يعتمد ماليًا بصفته مسئول المناديب.
- «إسناد إلى مندوب» في قائمة أصنافه بانتظار المعالجة ينقل صنفًا عاديًا واحدًا راجعَه المخوّل ولم يبدأ تسعيره إلى مندوب عادي نشط. ترك الصنف دون نقل يبقيه لدى المسئول ليكمل التسعير والشراء بنفسه.
- الإسناد يغير `delegateId` ووقت الوصول `delegateAssignedAt` للبند نفسه. تبقى حالته وطلبه وروابط الصيانة وPMV2 والتشغيل وبقية أصناف الطلب والمراجعة والاعتمادات كما هي. تحفظ الحركة والتدقيق في المعاملة نفسها، ويُخطر المندوب بعد نجاحها.
- لا نقل للصيانة الخارجية؛ إذا اختاره المستودع يستلم الأصل أو يرفض بسبب إلزامي، ويطلب تغيير المندوب في السبب ليقرر المستودع إعادة الإرسال. ليست هذه الصلاحية طريقًا لنقل عهدة تعويض مرتجع المورد؛ بنود خطط التعويض تستكمل مسارها الخاص بالمندوب نفسه.
- يظهر حساب مسئول المناديب النشط افتراضيًا في نموذج المراجعة المشترك لكل المراجعين المخولين. تظل الاختيارات اليدوية والإسنادات الحالية ومختلفة المندوبين محفوظة، ولا تكتب استجابة الدليل المتأخرة فوقها. إذا تعددت حسابات المسئول النشطة يُقترح أقل معرف؛ عند عدم وجود حساب لا يُختار مندوب عادي عشوائيًا، ويبقى الاختيار اليدوي متاحًا.
- الدور خيار جديد عند إنشاء المستخدم أو تعديله؛ لا ينشئ التطوير حسابًا ولا يغير دور حساب موجود تلقائيًا.

## الصلاحيات وسلامة النقل

- للمنح المركزية فحص خاص بالاستعلام `purchaseOrders.delegateAssignmentOptions` والإجراء `purchaseOrders.assignOwnDelegateItem` للمسئول الفعلي النشط فقط. الخيارات أسماء ومعرفات المناديب النشطين دون فتح دليل المستخدمين العام.
- يقرأ الإجراء المالك الحالي للبند وطلبه والحسابين تحت الأقفال داخل معاملة، ويرفض حالة ما قبل المراجعة والتسعير السابق والحزمة والمصادر المستثناة أو المفقودة. تحسب علامة أهلية الواجهة من المصدر نفسه باستعلامات مجمعة بحد500؛ لا تعد العلامة إذنًا للكتابة.
- بعد النقل تُرفض الكتابة/التسعير من نافذة قديمة للمسئول. تحديثات التسعير تقارن المندوب المتوقع في شرط الكتابة وتعيد فحص الملكية؛ لا تكفي حالة pending وحدها.
- المندوب العادي وصلاحيات المراجعة والحسابات والإدارة والمستندات المالية تبقى بحدودها السابقة. يحتفظ المسئول بنسخة مستند المندوب وبنطاقه فقط، بما في ذلك قيود المستند الرسمي المجمع ومفاتيح الصور والمرفقات.

## SQL يدوي

ملفا `01_role_copycmms2.sql` و`02_role_cmms.sql` يحوي كل منهما فحصًا ثم أمر ALTER واحدًا ثم تحققًا. يضيف الأمر `delegate_manager` في آخر ENUM الخاص بـusers.role مع المحافظة على القيم22 السابقة وترتيبها والافتراضي user وعدم قبول NULL. قارن النتيجة الحالية قبل التنفيذ؛ إذا كانت مختلفة فلا تستبدل قيمًا إضافية دون مراجعة.

لا أعمدة أو جداول أو فهارس جديدة لهذه الميزة، ولا ترحيل حسابات أو Backfill. يجب تطبيق ENUM قبل إسناد الدور لحساب. أوامر الصيانة الخارجية السابقة مستقلة وتظل مطلوبة لتشغيل تطويرها إن لم تطبق بعد.

لم ينفذ الوكيل اتصال قاعدة أو SQL أو تعديل بيئة أو نشرًا. القبول الحي بعد SQL يشمل مراجعة طلب متعدد الأصناف، إبقاء صنف للمسئول ونقل أصناف أخرى لمناديب مختلفين، تسعير كل منهم لأصنافه فقط، ثم الدورة المالية الحالية؛ واختبار قبول/رفض أصل الصيانة الخارجية وإعادة تعيينه من المستودع فقط.
