# مستندات طلبات المستودع — 2026-11-07

وافق المستخدم على إضافة «العمليات | المستندات» داخل المصادر الثلاثة في
`/scheduled-maintenance/warehouse-requests` فقط. مركز المستندات خارج نطاق التعديل.

## العرض

- العمليات افتراضية عند فتح الشاشة أو تغيير المصدر؛ مكوناتها وإجراءاتها السابقة كما هي.
- `panel=documents` يفتح المستندات؛ روابط `source` و`ticketId` القديمة محفوظة.
- تعرض المستندات الحالية DLV وWIS وRTN المرتبط بسند الصرف. لا إنشاء سند أو رقم جديد.
- بطاقة برقم السند ونوعه ومصدره ومرجع العملية/عنوانها والصنف والكمية والمستلم والمخزن والمنفذ والتاريخ.
- WIS يعرض أول مادة وعدد المواد، وكل بنوده في التفاصيل. المصدر المتعدد يميز بالبطاقة، ومراجع البنود محفوظة.
- بحث فوري برقم السند/البلاغ/المهمة/أمر الصرف أو المادة أو المستلم والمخزن واللوت، مع أرقام عربية/إنجليزية، والأحدث افتراضيًا وإمكان الأقدم.
- قراءة 20 سجلًا افتراضيًا، بحد50. البحث في بنود WIS كلها قبل الترقيم، ولا يعتمد على نص مختصر في البطاقة.
- التفاصيل والعرض والتنزيل والطباعة تعيد جلب المستند. قوالب الطباعة الموجودة تستخدم دون تغيير، مع عداد السند القائم.

## مصادر الربط

- التذاكر: `delivery_documents.ticketId` أو سلسلة `ticket_team_delivery_links → needs → assignments → tickets`.
- التشغيل: `operational_issue_deliveries → items → orders`.
- PMV2: سياق حركة التنفيذ مع المهمة والبند المطابقين؛ أفعال `material_issue_linked/material_issue_link_pending` ذات JSON صالح؛ أو `pmv2_material_usages`. يشمل العرض الفترة قبل إعلان الاستهلاك. يدعم مرجع WIS التاريخي إلى طلب مادة PMV2 مع مطابقة DLV/الحركة.
- المصدر يعتمد المعرّفات المحفوظة ووجود الأصل، وليس تشابه اسم المادة أو بادئة رقم المستند. المصدر القديم الذي فُقد رابطه لا يُصنف تخمينًا.
- UNION ثم تجميع المصدر يمنع تكرار DLV عند تعدد أدلة ارتباطه. يربط RTN عبر `sourceDeliveryDocumentId` فقط؛ مرتجعات المورد المستقلة ليست مستندات هذا الصرف.
- WIS الموجود يظهر في المصادر التي تضم مواد منه، ويُقرأ كاملًا للمستودع المخول. لا يظهر رأس تجميعي إذا فُقد أحد سندات DLV التابعة له.

## الصلاحيات والأداء

- `warehouseRequestDocuments.list/detail/recordPrint` تمنح للمستودع والمالك والأدمن النشطين فقط.
- حارس capability المركزي يمنح الأسماء صراحة للمستودع؛ الإجراء القائم warehouseProcedure والخدمة يفحصان الهوية الفعلية. الخدمة تعيد قراءة الدور والنشاط من users لكل عملية، دون الاستناد إلى إسقاط دور مراقب كأدمن.
- مصدر السند وأصله يفحصان في SQL عند التفاصيل والطباعة؛ لا يُعاد استعمال قرار القائمة لاحقًا، ولا يوجد cache للصلاحيات.
- مصدر القائمة يجمع السندات بعلاقات SQL؛ العدد والبحث والترتيب والترقيم قبل إرجاع الصفوف. لا قارئ صلاحية أو مستند داخل حلقة، ولا تحميل كل المستندات للمتصفح. ثلاث استعلامات ثابتة للقائمة: الهوية، العدد، الصفحة.
- فشل البنية التحتية يمر كخطأ، ولا يتحول إلى قائمة فارغة أو رفض عادي.
- لم تُغيّر كتّاب الصرف أو المرتجعات أو المخزون أو الإجراءات المالية أو القوالب أو مركز المستندات.
